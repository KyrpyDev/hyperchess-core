### 5. Adopted the law and implemented it everywhere

> A HyperChess notation string is self-contained. Everything needed to reconstruct the
> position, or to resolve the move, is inside the string. No side table, no lookup, no
> defaulting of a field that could not be read.

- **`io/hsan_parse.rs` and `io/hsan_export.rs` rewritten** (v2.0.0). Destination anchored at
  the end of the string with ranks matched `1[0-2]|[1-9]`; piece alphabet `KQRBNEH`; a new
  `CastleSide` field keeps the two castles distinct; mandatory file/rank/file+rank
  disambiguation; capture marker placed by construction; check/mate markers now emitted;
  the piece letter is applied during resolution.
- **HFEN made strict.** `CastleRights::from_hfen_checked`, `parse_ep_square_checked`, and
  `Result`-returning numeric fields. `is_promotion_type_char` restricts the `id:Type` type half
  to `Q R B N E H`, so `M:K` can no longer smuggle in a second king.
- **Syntax split from position legality.** `parse_hfen` validates the string;
  `Board::from_hfen` additionally calls the new `validate_king_count`. This resolved a genuine
  contradiction in the spec (§10 blessed the empty board, §11 demanded one king per side) and
  kept the engine's own fragment-based movegen tests expressive.
- **HPGN-I identity is now verified** against the piece on the source square via the new
  `split_identity`, so a wrong or impossible prefix is an error rather than a comment.
- **The TS SDK no longer erases identity on every move.** `getBoardHfen` re-serialized from a
  type-only snapshot and its output is fed straight back into the WASM engine by
  `generateLegalMoves` / `applyMove` / `isInCheck`. Added optional `Piece.identity`, a new
  identity-aware `parseHfenPosition`, identity merging in `snapshotFromWasmBoard` sourced from
  the engine's own HFEN (so **no WASM rebuild was required**), and `id:Type`-emitting output.
- **dev-web rendered every promoted piece as its original type.** `parseHfenToPieces` resolved
  `M:Q` through the identity map left-half-first, so promoted queens displayed as pawns in both
  the 2D and 3D boards. Added a separate `TYPE_PIECE_MAP`; the current type now wins. Its
  `START_HFEN_I` constant also carried `-` for castling and was corrected to `KQkq`.
- **The vendored `hyperchess-rules` inside `hyperchess-boilerplate-app`** (which its crates
  actually build against, by path) was re-synced to an exact mirror of upstream.

## Decisions of record

- **The self-contained law is binding.** No parser may default a field it could not read; no
  serializer may place a character by counting from the end of a string; no format may require a
  side table. `docs/baremetal-hyperchess-notations-v01.md` is normative and wins over any other
  doc or implementation.
- **Syntax and position legality are deliberately separate.** `parse_hfen` = "is this a
  well-formed HFEN string" (accepts fragments, used by movegen tests); `Board::from_hfen` =
  "is this a position a game can be in" (enforces one king per side). Do not collapse them,
  and do not relax the king check in `from_hfen`.
- **The canonical start's castling field is `KQkq`, never `-`.** Rights are only ever cleared,
  never granted, so a start written with `-` can never castle again. This bit the project once
  already; three separate copies of the constant now agree.
- **`id:Type`'s type half is restricted to `Q R B N E H`.** Promotion is the only way a piece's
  type can differ from its identity's starting type. `M:K` must stay rejected.
- **The HPGN-I identity prefix is verified, not carried.** Reverting this would turn the game
  record back into an unverifiable comment.
- **Identity remains metadata** — never an input to move generation. That is what makes it
  impossible for identity handling to change what is legal.
- **The identity alphabet overlaps the type alphabet on purpose** and identity wins in a
  position field. The King's identity is `G`; identity `K` is a Hawk. Documented as the
  "overlap trap"; do not "fix" it by renaming.
- **`hyperchess-live-stream` stays its own codebase-memory project** (prior decision, re-
  confirmed): `projects-kyrpy-projects-kyrpy-hyperchess-hyperchess-live-stream`. Do not
  un-gitignore it to pull it into the parent index.
- **Do not delete codebase-memory `.stage.*` files without an immediately-preceding
  `/proc/*/fd` check** — a new indexer run can claim one between two checks.

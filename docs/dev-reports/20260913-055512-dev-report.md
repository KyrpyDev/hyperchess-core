### 3. Gitignores across the workspace

The workspace root protected none of its large generated trees. A bare `git add -A` there would
have staged roughly **44 GB**: `hyperchess-builds/` (~26 GB) and
`hyperchess-apps/hyperchess-boilerplate-app/target/` (~18 GB).

Root `.gitignore` now covers both, plus the agent/tooling caches (`.codebase-memory/`,
`.gitnexus/`, `.codex/`, `.archive/`, `.claude/worktrees/`, `graphify-out/`) and per-language

three existing sub-repo ignores were extended with the same cache set.

The notable judgement call: **`hyperchess-apps/.gitignore` deliberately does not ignore
`vendor/`.** The vendored `hyperchess-rules` crate is checked in on purpose — the app's crates
build against it by path — so only `vendor/**/target/` is excluded.

Empty sub-projects (`hyperchess-api`, `hyperchess-mcp`, `hyrperchess-portal`) were skipped: with
no files, an ignore file would exist only to create the directory in git.

## Decisions of record

- **All decisions from the two 2026-09-12 reports remain binding.**
- **`.claude/worktrees/` is gitignored in every repo** — a worktree whose `.cargo/config.toml`
  `target-dir` is relative will drop a multi-hundred-MB cargo cache inside it. After removing a
  worktree, check for a leftover `hyperchess-builds/` sibling under the worktrees directory.
- **`hyperchess-apps/vendor/` stays tracked.** Do not "tidy" it into the ignore file; the
  boilerplate app builds against the vendored crate by path.
- **`hyperchess-builds/` must never be staged.** It is the shared cargo target sink for every
  sub-project and is ~26 GB.
- **`feat/engine-open-source-kit` and the three `worktree-*` branches are fully contained in
  their mains.** The branch refs still exist; only the working directories were removed.

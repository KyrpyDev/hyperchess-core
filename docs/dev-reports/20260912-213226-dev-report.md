The previous report's open item said the `feat/engine-open-source-kit` worktree "carries its own

wrong: the branch was **0 commits ahead of main and 15 behind**, and its only working-tree

Discarded the mode churn, then merged `fix/notation-self-contained-law`, which fast-forwarded

`cargo test -p hyperchess-rules` — **165 passed, 0 failed**, including all 16 notation-law tests.

### 2. dev-web advanced to the limit of what a commit can do

`hyperchess-dev-web` consumes the engine as a git dependency **tracking the default branch**,
with `Cargo.lock` pinned to gitlab `48531dd`. The lock cannot be re-pinned until the fix reaches
`gitlab/main`. The operator chose the branch + merge-request flow over pushing main directly, so:
the fix branch was pushed and **MR !1** opened in each repo. The `Cargo.lock` bump is the single
step still outstanding.

### 3. CI caught two things local testing had not

The first pipeline (19) failed **both** lint jobs. Neither `cargo fmt --check` nor
`cargo clippy -- -D warnings` had been run locally — a genuine gap in the previous report's
"verified" claim, now closed.

- **`rust:fmt`** — four spots in the new code did not match rustfmt output. `cargo fmt --all`,
  committed separately (`688f0ff`) as a no-behaviour-change commit.
- **`rust:clippy`** — `manual_isolate_lowest_one` at
  `crates/hyperchess-rules/src/core/bit_twiddles.rs:38`, in code this branch never touched.
  **Pre-existing**, surfaced only because CI's `rust:1-bookworm` image is Rust **1.98.0** while
  local development here is **1.96.0**, where the lint does not exist. It blocks any merge
  request to this repository, not only this one.

  Clippy suggests `b.isolate_lowest_one()`. That method is still **unstable on 1.96**
  (feature `isolate_most_least_significant_one`), so taking the suggestion would raise the
  crate's effective minimum toolchain purely to satisfy a lint. Allowed the lint instead, with
  `unknown_lints` also allowed so the attribute stays harmless on older clippy. Committed
  separately (`71dc6bb`) to keep diff attribution honest.

## Decisions of record

- **Everything from `20260912-103200-dev-report.md` remains binding** — the self-contained law,
  the syntax/legality split, `KQkq` in the canonical start, the restricted `id:Type` type half,
  verified HPGN-I prefixes, identity as metadata, and the deliberate identity/type alphabet
  overlap.
- **`feat/engine-open-source-kit` is now a descendant of the notation fix, not a parallel copy.**
  It had no unique commits. Do not re-introduce a hand-maintained duplicate of the notation
  files there; keep it merged forward instead.
- **Never run only the test suites before pushing to this repo.** CI gates on
  `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets -- -D warnings`, and
  both must be run locally first. The clippy gate is toolchain-sensitive: CI is on Rust 1.98
  while local is 1.96, so CI can fail lints that cannot even fire locally.
- **`lsb()` keeps `b & b.wrapping_neg()` on purpose.** The clippy-suggested
  `isolate_lowest_one()` is unstable below Rust 1.98; do not "fix" the allow by adopting the
  method until the minimum toolchain moves.
- **Mode-only churn (644 -> 755) is not committed.** ~65 files in core and the equivalent in the
  worktree carry it with zero content change. It is copy noise; committing it would record
  "docs are now executable" as intent.
- **The umbrella repo deliberately tracks only a handful of files.** Its working tree is 45 GB
  and `hyperchess-builds/` (~25 GB of cargo caches) is **not** in `.gitignore`, so a blanket
  `git add -A` there would stage it. Only `.gitignore` and the four authored/edited doc files
  were committed.

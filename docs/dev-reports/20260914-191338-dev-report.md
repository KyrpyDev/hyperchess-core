## What was done

**Node 20 deprecation fix (commit `5dae05f`)**
- Root cause: `pnpm/action-setup@v4`'s `action.yml` declares `using: node20`; GitHub Actions
  runners are deprecating Node 20 for actions and force-running such actions on Node 24 instead
  (hence the warning, not yet a hard failure).
- Confirmed `pnpm/action-setup@v6`'s `action.yml` declares `using: node24` natively.
- Bumped the pin `pnpm/action-setup@v4` → `@v6` in all three workflow files:
  `.github/workflows/ci.yml`, `.github/workflows/release-npm.yml`,
  `.github/workflows/security.yml`.
- No change to which pnpm version gets installed — that's still driven by
  `"packageManager": "pnpm@11.5.0"` in `package.json`; v6 only changes the action's own runtime.

**nanoid high-severity vulnerability fix (commit `9b5a39b`)**
- The re-triggered "Security audit" workflow run (`34843353447`) failed on
  `pnpm audit --prod --audit-level high`: `nanoid` `<3.3.18` is vulnerable to an indefinite loop
  when a custom generator size is zero ([GHSA-2v37-7h3g-55p8](https://github.com/advisories/GHSA-2v37-7h3g-55p8)),
  pulled in transitively via `packages/board > vue > @vue/compiler-sfc > postcss > nanoid`. This
  audit was already failing on the prior scheduled run (11:34:43 UTC, before this session's first
  push) — pre-existing, unrelated to the Node 20 fix.
- Attempted a `pnpm.overrides` block in root `package.json` first; `pnpm install` warned that
  pnpm 11.5.0 no longer reads the `pnpm` field from `package.json` — overrides now live in
  `pnpm-workspace.yaml`.
- Reverted the `package.json` change; added `overrides: { nanoid@<3.3.18: ">=3.3.18" }` to
  `pnpm-workspace.yaml` instead.
- `pnpm install` re-resolved the lockfile: the vulnerable `nanoid@3.3.16` entry is gone, leaving
  only the already-patched `nanoid@5.1.16`.

## Decisions of record

- **`pnpm/action-setup` pinned to `@v6`** (was `@v4`) in all three `hyrperchess-core` workflows.
  Do not revert to `@v4` — it bundles a `node20` runtime that GitHub Actions is deprecating.
- **nanoid pinned via `pnpm-workspace.yaml` `overrides`, not `package.json`'s `pnpm` field.**
  pnpm 11.5.0 (this repo's pinned `packageManager`) silently ignores overrides declared in
  `package.json` — a future dependency-override change must go in `pnpm-workspace.yaml` or it will
  have no effect (and `pnpm install` will only warn, not error).
- Both fixes were pushed directly to `main` on both remotes without a PR — matches how this
  session found the branch (already tracking `github/main`, no open feature branch), and the user
